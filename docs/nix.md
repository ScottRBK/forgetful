# Nix Guide

Run and develop Forgetful with [Nix flakes](https://nixos.wiki/wiki/Flakes).
`uv.lock` stays the single source of truth for exact dependency versions —
Nix builds the locked environment reproducibly. The Docker setup under
`docker/` is untouched; this is an alternative, not a replacement.

## Prerequisites

- Nix with flakes enabled (`experimental-features = nix-command flakes` in
  `~/.config/nix/nix.conf`, or NixOS / nix-installer which set it up for you)
- Supported systems: `x86_64-linux`, `aarch64-linux`, `aarch64-darwin`
  (`x86_64-darwin` is intentionally omitted)

## Dev shell

```bash
nix develop
```

You get the locked Python environment plus `uv`, `ruff` and `pytest`, with
`PYTHONPATH` pointed at the repo. First entry installs the pre-commit hooks
automatically.

Use `uv` for lock operations only (`uv add …`, `uv lock`) — never
`uv sync`/`uv run` inside the shell; Nix owns the environment.

```bash
uv lock --check
pytest tests/integration/ -q
```

## Run

```bash
nix run .#forgetful-ai -- --transport http --port 8020
```

(`nix run .` works too — `forgetful-ai` is the default app.) Anything after
`--` is passed to Forgetful; see `forgetful --help` for transports and flags.
For MCP clients, point a stdio server at `nix run .#forgetful-ai`.

## Build

```bash
nix build .#forgetful-ai -o result-forgetful   # wrapped app package
nix build .#docker -o forgetful.tar.gz         # OCI image (~195M)
```

The image repo is `forgetful` — same as `ghcr.io/<owner>/forgetful` in
`.github/workflows/build.yml` and the `forgetful:latest` default in
`docker/docker-compose.yml` (package name stays `forgetful-ai`). The tag is the
sanitized version (`+` → `-`, since `+` is invalid in Docker tags): local builds
give `forgetful:0.0.0-dev`; release builds inject the real tag:

```bash
FORGETFUL_VERSION=$(git describe --tags) nix build --impure .#docker
```

Load and add the CI-equivalent aliases (`buildLayeredImage` carries one tag, so
`latest` / `major.minor` are plain `docker tag`s after load):

```bash
docker image load -i forgetful.tar.gz
docker tag forgetful:<version> forgetful:latest
# optional GHCR aliases:
# docker tag forgetful:<version> ghcr.io/<owner>/forgetful:<version>
# docker tag forgetful:<version> ghcr.io/<owner>/forgetful:latest
docker run --rm -p 8020:8020 forgetful:latest
curl -sf http://localhost:8020/health
```

## Versions

Hatch-vcs has no `.git` inside Nix builds, so the version defaults to
`0.0.0+dev` (same spirit as the Dockerfile's `VERSION` default). For a real
tag, inject it release-side:

```bash
FORGETFUL_VERSION=$(git describe --tags) nix build --impure .#forgetful-ai
```

## Hooks, format, checks

- Hooks (`nixfmt`, `deadnix`, `statix`, `ruff`, `typos`) run at commit time
  from the dev shell: `pre-commit run --all-files`
- `nix fmt` rewrites the tree with the same hook set
- `nix flake check` runs the sandboxed pre-commit check plus the test suite
  (see [Tests](#tests))

`.pre-commit-config.yaml` is generated by git-hooks.nix and gitignored — do
not commit it, and regenerate it by entering `nix develop`.

Spelling allowlist lives in `_typos.toml` (e.g. the intentional `"FoRgEtFuL"`
in tests, personal notes in `org_knowledge_proposal.md` which is excluded).

## Tests

The sandbox-runnable tiers run as a flake check:

```bash
nix flake check                                    # includes the test derivation
nix build .#checks.x86_64-linux.testsPkg           # the suite on its own
```

That covers `tests/integration` (stubbed I/O) and `tests/e2e_sqlite`
(in-memory SQLite) — currently 1859 passed, 11 skipped. `tests/e2e` needs a
real PostgreSQL and is excluded twice over: by directory scoping and by
pytest.ini's `-m "not e2e"`. Run it yourself with `docker compose` per
`docker/`.

The suite pulls the FastEmbed embedding and reranker models from Hugging Face
and a tokenizer blob from OpenAI's blob store, which the Nix sandbox has no
access to. `nix/test-fixtures.nix` vendors those into the check environment,
revision-pinned and sha256-verified, and sets `HF_HUB_OFFLINE` /
`FASTEMBED_LOCAL_FILES_ONLY` so a missing fixture fails loudly instead of
reaching for the network. Bumping `EMBEDDING_MODEL` or `RERANKING_MODEL` in
`app/config/settings.py` means updating that manifest — a stale hash fails the
build rather than silently fetching something else.

Ad-hoc runs in the dev shell still work and are usually quicker while
iterating:

```bash
nix develop -c pytest tests/integration/ -q
```

## Non-flake entry points

`default.nix` and `shell.nix` exist for tooling without native flake support.
Both delegate to the flake — `nix-build .` produces the same output path as
`nix build .#forgetful-ai`, so the compat path cannot drift from the flake.
Don't add shell or package definitions there.

```bash
nix-build .                                        # the wrapped app package
nix-shell .                                        # the flake's dev shell
```

## Dependency freshness

Dependabot updates flake inputs (`nix`) and pinned Actions
(`github-actions`) weekly, grouped into one PR per ecosystem. Python
dependencies are deliberately excluded: everything in `pyproject.toml` is
exactly pinned, including audited transitive versions, and scheduled bumps
would overwrite that audit trail.

- **Who reviews:** a maintainer. Bump PRs change only `flake.lock`; read them
  as "which inputs moved and does CI agree".
- **How to revert:** revert the merge commit. The inputs are pinned by the
  lock, so a revert fully restores the previous set.
- **How to bump by hand:** `nix flake update <input>`, or `nix flake update`
  for all of them.

## Build cache

A public cache exists at <https://forgetful.cachix.org>. The flake does not
consume or push to it yet; wiring `nixConfig` and the CI push is separate
work.

## Nix design decisions

Recorded so nobody re-derives them.

| Axis | Choice | Why |
| --- | --- | --- |
| nixpkgs channel | `nixos-unstable` | an app wanting current packages; the estate's stable pin isn't relevant to an upstream-facing repo |
| Release | tags | hatch-vcs derives the version from tags |
| `follows` edges | `pyproject-nix`, `uv2nix`, `pyproject-build-systems`, `git-hooks-nix` → `nixpkgs`; `flake-parts` → `nixpkgs-lib`; `git-hooks-nix` → `flake-compat` | one nix source in the closure, so `nix flake update nixpkgs` moves everything together. `flake.lock` holds 8 nodes |
| Source filtering | allow-list via `lib.fileset.toSource` | the tree is ours and the build reads a subset — see [Rebuild scope](#rebuild-scope) |
| Binary cache | public Cachix | public, upstream-facing repo; the estate attic is the internal channel |
| Version identity | scm-stamp (`FORGETFUL_VERSION` → `SETUPTOOLS_SCM_PRETEND_VERSION`) | pure builds have no `.git` and must never crash; they get `0.0.0+dev`, releases stamp the tag |
| Test tiers | sandbox tiers as checks; PostgreSQL tier opt-in | `nix flake check` with zero authored checks passes while proving nothing |
| Architectures | `x86_64-linux`, `aarch64-linux`, `aarch64-darwin` | see caveat below |
| flake-compat | included | house default; zero cost to flake-native users |

### Rebuild scope

The package `src` is an allow-list, so only these paths legitimately change the
package derivation hash:

- `app/`, `main.py`, `alembic.ini`, `alembic` — what `installPhase` consumes
- `pyproject.toml`, `uv.lock` — read at eval time by uv2nix through
  `workspaceRoot`, which is why they stay outside the fileset: dependency
  changes must still invalidate the build

Docs, CI and test-only commits leave the package hash alone. Before the
allow-list, appending a comment to `README.md` invalidated the package and
everything downstream of it.

**Known limitation:** `forgetful-env` embeds the project built from the raw
`workspaceRoot`, so unrelated commits can still rebuild the Python
environment. The allow-list reduces package churn, it does not eliminate it.
Splitting the venv from the project tree is the separate fix and is not done.

### Architecture caveat

Three systems are declared, but only `x86_64-linux` has ever been built here.
`nix flake check` reports the other two as omitted incompatible systems, which
proves nothing about them — a declared system without a builder is an
intention, not a guarantee. This is Python, so the cross-architecture builds
are expected to work, but they are untested until a builder or CI job exists.

## Troubleshooting

- `warning: Git tree … is dirty` — benign; Nix tells you the evaluation used
  your worktree state. Commit for byte-identical reproducibility.
- `pre-commit: command not found` in an old shell — re-enter `nix develop`
  (the shell installs hooks and PATH on entry).
- `aarch64` packages evaluate but won't *build* here — that needs an aarch64
  builder or CI (`nix build --dry-run` proves the closure resolves).
- `error: attribute 'runCommand' missing` (or similar) in
  `nix/test-fixtures.nix` — the fixtures are `callPackage`d, so anything they
  need must be a function argument rather than reached through `pkgs`.
- First `nix develop`/`nix build` downloads a lot (toolchain + all locked
  wheels) — subsequent runs are cached.
